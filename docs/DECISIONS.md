# Decisions

Format: decision — reason — alternative considered.
- Node 24 LTS installed user-locally in `~/.local/node` — no Homebrew on host, user approved — Homebrew/nvm.
- Docker runtime is OrbStack — installed by user — Docker Desktop.
- Prisma pinned to 7.10.1 (stable) — npm `latest` tag points at 8.0.0-rc; Better Auth peer range is `^7` — Prisma 8 RC.
- Prisma client generated to `src/generated/prisma` (gitignored) via `prisma-client` generator + `@prisma/adapter-pg` — Prisma 7 requires explicit output + driver adapter — legacy `prisma-client-js`.
- Extensions created in the init migration SQL, not `datasource.extensions` — that needs the `postgresqlExtensions` preview — enabling the preview.
- tsvector columns are trigger-maintained (`atlas_*_tsv()` functions); GIN indexes on them are declared in schema.prisma (Prisma allows Gin on Unsupported) — keeps `migrate dev` drift-free — GENERATED columns.
- HNSW indexes are *partial* (`WHERE embedding IS NOT NULL`) in a hand-written migration — Prisma can't express HNSW and would drop full indexes on each `migrate dev`, but ignores partial ones — expression index / ignoring drift. KNN queries always include the predicate.
- Next.js `cacheComponents` / `partialPrefetching` disabled — app is a client-heavy workspace backed by dynamic route handlers; avoids prerender constraints on DB-backed pages — adopting Cache Components.
- MSW dropped: MSW 3 did not intercept Node 24 fetch in Vitest (a request leaked to Google). LiveYouTubeClient takes an injectable fetch; tests use an in-memory transport — MSW.
- Fixture mode meters quota exactly like live mode — UI quota meter and lane logic are exercised in the demo — skipping metering in fixture mode.
- Fixture dataset is committed (~7 MB, deterministic seed 1337) and includes scheduled future uploads hidden until their publishedAt passes, so incremental sync finds new videos over time (`FIXTURE_NOW` overrides the clock) — generating at setup.
- Job events for user-initiated jobs go only to `events:user:{id}`; background jobs go to `events:global` — avoids duplicate delivery on one SSE connection — publishing to both.
- Incremental sync and stats refresh bypass the response cache — sync exists to see fresh data — relying on the 30 min first-page TTL.
- bull-board runs inside the worker on 127.0.0.1:BULL_BOARD_PORT; the web app proxies `/api/admin/queues` for ADMIN users — no maintained Next.js adapter — mounting via Hono.
- Custom job IDs use '-' separators (`ingest-UC…`, `sync-<id>-<hour>`) — BullMQ 6 rejects ':' in custom IDs — spec's `ingest:{id}` literal.
- Web process embeds search queries in-process (lazy transformers.js singleton, warmed by instrumentation; 2 s timeout → keyword fallback) — simpler than a BullMQ RPC and no worker round-trip — worker RPC via waitUntilFinished.
- `EMBEDDING_PROVIDER=hash` (feature hashing) added for offline/CI tests — keeps integration tests deterministic and fast; local MiniLM remains the default — downloading the model in CI.
- Topic rows are created on first sighting (needed for canonical merging + counts) but only topics with ≥ 2 videos become graph nodes / list results — spec says *materialize a node* at ≥ 2 videos.
- MiniLM cosine is rescaled (cos−0.12)/0.48 → 0..1 before the 0.55 weight — raw cosines for related text sit around 0.15–0.6 so unscaled scores never cleared the 0.35 threshold — per-channel max-normalization.
- If a channel has any MANUAL niche, all automatic labels are removed on reclassification — 'manual always wins' — mixing manual + automatic labels.
- Taxonomy lives in `src/server/taxonomy.ts` (seed + classification + fixture generator import it) — server code can't import from prisma/ via the @ alias — duplicating it.
- Graph edge provenance: undirected top-k kinds store `evidence.from` (which endpoint picked the edge) so incremental rebuilds are exact unions of per-node top-k — recompute-all-neighbors or asymmetric approximations.
- PUBLISHED edge weight = 0.5·log-popularity + 0.5·recency (not a constant 1) — lets per-hop top-k fan-out pick representative videos — constant ownership weight.
- Spec thresholds kept as-is (SIMILAR cosine ≥ 0.75, CO_TOPIC weighted Jaccard ≥ 0.2); on the demo dataset this yields few channel↔channel semantic edges because most demo channels sit in distinct subniches — lowering thresholds to densify the demo.
- Topic extraction drops corpus boilerplate with max_df = 8% (once ≥ 200 docs) and caches label→topic resolution in Redis — fixture sentence templates otherwise dominated cross-channel topics — a hand-curated stopword list only.
- Better Auth session cookie cache disabled — revocation/account deletion must take effect immediately — 60 s cookie cache.
- Local traversal fan-out per hop is 40 / 12 / 6 and does not expand through niche hubs or videos — keeps neighborhoods legible and bounded — uniform fan-out.
- OpenAPI is generated from the shared Zod contracts with Zod 4's native `z.toJSONSchema` — no maintained Zod→OpenAPI library needed for Zod 4 — @asteasolutions/zod-to-openapi.
- Account deletion also removes the user's uploaded transcripts and discovery history — they are personal contributions — keeping them anonymized.
- Semantic search hits below a similarity floor (0.28 for local MiniLM, 0.05 for the hash provider) are dropped before RRF — semantic lists always return k items and otherwise inject unrelated niches into hybrid results — no floor.
- Client-bundle secret check greps secret *values* plus server-only key names; the name `BETTER_AUTH_SECRET` is allowed because Better Auth's isomorphic env getter references it (returns undefined in the browser) — failing the build on a library string.
- E2E runs in an isolated environment (`scripts/e2e-server.ts`: DB `atlas_e2e`, Redis prefix `atlas-e2e`, port 3100, `NEXT_DIST_DIR=.next-e2e`, hash embeddings, 14 seeded channels) so it can run next to `pnpm dev` — sharing the dev DB/server.
- `window.__atlas` exposes the controller + graph for Playwright (node positions on a WebGL canvas aren't in the DOM) — pixel-guessing in tests.
- Session-gated UI branches on React Query `isPending`, not `isLoading` — on the server and first client render the query is pending-but-idle, so `isLoading` was false and caused hydration mismatches.
- Zustand `persist` uses `skipHydration` + `rehydrate()` after mount — synchronous localStorage hydration made the first client render differ from the server.
- lucide-react no longer ships brand icons; the YouTube connect button uses a generic link icon — bundling a YouTube logo.

## Spec-gap pass (2026-11-09)
- **Sigma driven directly, not via `@react-sigma/core`** — the atlas needs imperative control (FA2 worker lifecycle, reducers fed from a mutable view state, expand/collapse, box-select, drag-pin) and the graph lives outside React; a thin controller (`src/lib/atlas/controller.ts`) was simpler than adapting react-sigma 6 to sigma 4's new styles API. The unused package was removed — alternative: `@react-sigma/core` components/hooks.
- **No ring border on niche nodes** — sigma 4's `@sigma/node-border` layer bindings and the node-backdrop border both failed to render a ring in our tests (whole node took the ring colour / a rectangle without border). Niche hubs are distinguished by size, `#4361FF`, and always-visible bold labels; `@sigma/node-border` was removed — alternative: a custom WebGL layer program.
- **Suggested subniches**: candidates are channels whose best automatic label is < `CLASSIFY_MIN_CONFIDENCE + 0.2` (or flagged low-confidence) and have no manual override; edges = SIMILAR/CO_TOPIC graph edges **plus** direct embedding cosine (≥ 0.45 local / 0.15 hash) because SIMILAR at 0.75 is too sparse; Louvain; clusters ≥ 3. Name = top two shared topics; parent = majority parent niche. Spec says SIMILAR graph only — alternative: SIMILAR only.
- **Accepting a suggestion is admin-only** (it changes the shared taxonomy everyone's atlas uses). The UI lives on `/admin`. Accept creates the subniche (centroid = mean member embedding), reclassifies members, links any member that still doesn't pick it up with its computed score, and marks graph nodes dirty. Dismissed/accepted suggestion IDs (hash of member IDs) are remembered in Redis — alternative: let any user propose taxonomy changes.
- **Default-layout preference** "local" opens the local graph around the user's last single selection (remembered per browser) when `/atlas` is opened without an explicit `?mode=` — alternative: a server-stored "last focus".
- **Reduced motion**: the user setting adds `.reduce-motion` on `<html>` (disables CSS transitions) and forces `MotionConfig reducedMotion="always"`; the OS `prefers-reduced-motion` is honoured independently.
- **Discover region/language**: passed as `regionCode` / `relevanceLanguage` to `search.list`. In fixture mode `regionCode` boosts channels from that country (the real API biases rather than filters); language is ignored because all fixture content is English.
- **"Load demo dataset"** in the empty atlas calls `POST /api/demo/load` (fixture mode only, signed-in, 3/hour) which enqueues the not-yet-ingested fictional channels through the normal ingest queue — alternative: instructing users to run `pnpm db:seed`.
- **Stale-while-revalidate** applied to UI-facing YouTube reads: channel details (+1 h), uploads first page (+15 min), video stats (+1 h); syncs and compliance still bypass the cache.
- **Status bar shows last sync** (most recent `lastSyncedAt`), via a new `sort=synced` option on `GET /api/channels`.
- **`pnpm typecheck` runs `next typegen` only when route types are missing** — running it while `next dev` is up rewrites watched files (`next-env.d.ts`, `.next/types`) and caused a reload loop; clean checkouts (CI) still generate them — alternative: always typegen.
- **Docker build uses placeholder env values** for `prisma generate`/`next build` (env.ts validates on import); real values come from the runtime environment. Nothing from build env is inlined into client bundles (verified by the CI secret check).
- **`onnxruntime-common` is a direct dependency** — `@huggingface/transformers` imports it without declaring it; it only resolved via pnpm hoisting and broke silently (semantic search fell back to keyword) when the hoisting changed. A unit test now imports transformers to catch this.
- **Health-check registry lives on `globalThis`** — Next bundles `instrumentation.ts` separately from route handlers, so a module-level Map left `/api/health` without the embeddings/queue checks.
- **Production image installs `openssl`** — the Prisma CLI (`migrate deploy` on container start) needs it on `node:24-bookworm-slim`.
- **E2E serves a production build (`next build` + `next start`)**, not `next dev` — two dev servers (developer's `pnpm dev` + e2e) each rewrite `next-env.d.ts` on start and kept triggering each other's reload loops; a prod build is also closer to production. `E2E_SKIP_BUILD=1` reuses the last e2e build.
- **Canvas e2e specs zoom onto their target node and wait for the initial layout + camera to settle** before pointer actions — on dense or cold layouts the cursor otherwise hit a neighbour (CI showed this as a flaky expand test).
- **`AUTH_RATE_LIMIT`** (auto/on/off) controls Better Auth's built-in limiter (auto = on in production); the isolated e2e environment sets it off because the suite signs up many users from one IP within seconds — alternative: spacing out e2e signups.

## YouTube collection round (2026-11-09)
- **Every corpus addition or refresh runs under an `ExpansionProposal`** — newer prompt overrides BUILD_SPEC §7.11's automatic syncs/stats/compliance refresh. Schedulers raise one pending SYSTEM proposal per kind (admin-approvable); deletion stays automatic — alternative: a standing "auto-approve" mode (explicitly forbidden).
- **Approval = session user + echoed scopeHash, single transition PENDING→APPROVED→RUNNING under a row lock**; agents/system can never approve; SYSTEM proposals need ADMIN; CLI approval only in fixture mode (seed) — alternative: signed approval tokens (no added security over a DB-checked proposal ID + hash).
- **Three enforcement layers**: dispatch only from APPROVED; `enqueueExpansion` refuses jobs not registered on a RUNNING proposal; every collection service calls `authorizeJob` (status, recomputed scope hash, job registered, execution deadline, target ∈ scope) before writing — alternative: worker-only check.
- **Child work (discovery ingests, backfill continuations, transcript fetches) is registered on the same proposal before enqueue**, so retries are idempotent (deterministic `x-<proposal>-<part>` job IDs) and nothing can run after completion/cancel.
- **Discovery selection is recorded once** (`actualResults.selected`, ≤ maxChannelsToAdd, skips channels already present); child ingests are authorized against that set; replays refused.
- **Upload history is committed per page in one transaction** (videos + coverage + checkpoint + proposal progress). A partially consumed page keeps its token + `pageOffset`, so bounds can stop mid-page without skipping items — alternative: collect IDs first, write later (lost work on crash, the previous behaviour).
- **Backfill runs in 10-page slices that re-enqueue at low priority** (priority 20) — keeps interactive work flowing.
- **Known limitation**: uploads-playlist page tokens are positional; uploads deleted mid-backfill can shift items across a saved checkpoint. New uploads only cause harmless overlap. `itemsSeen` vs `totalResults` is reported so drift is visible.
- **Thumbnails stored as a JSON array on the row** (variant, url, width, height) + preferred `thumbnailUrl` — no image downloads; alternative: a Thumbnail table (5× rows for no query benefit).
- **FieldCoverage table** (one row per entity × group) with deterministic IDs `cov_<entity>_<group>` for bulk upserts; resolved statuses advance `lastSuccessAt`/deadline, NOT_RETURNED/ERROR only record the attempt — alternative: JSON column per row (hard to aggregate).
- **Partial responses**: a missing *part* changes no columns; a missing field inside a returned part with known semantics (likes hidden, comments disabled, hidden subscribers) is stored as NULL + UNAVAILABLE detail, never 0.
- **Retention classes**: API_METADATA 30 d; API_STATISTICS 30 d (36 months only with the derived-metrics amendment flag, live mode); AUTHORIZED_DATA 30 d + immediate revocation purge; USER_CONTENT/FIXTURE not API data. Derived data inherits by cascading with its source row; orphan topics are pruned.
- **Transcript identity (video, source, language, ownerKey)**; `ownerKey = ownerUserId ?? "corpus"` because Postgres treats NULLs as distinct in unique indexes. `Video.hasTranscript`/`transcriptStatus` describe the shared corpus only, so they never leak private transcripts.
- **Private transcripts never feed shared derived data** (topics, AI extraction, global search, graph attrs) — alternative: let owners opt in to share (product decision for later).
- **Owner captions: one preferred track per video** (manual > ASR, English first) to bound the 250-unit cost; skipped entirely when `contentDetails.caption = false`.
- **Fixture responses are enriched deterministically at read time** (thumbnail dims, standard/maxres for some videos, ~12 % hidden likes, ~6 % disabled comments, status/topic parts) instead of regenerating the committed 7 MB dataset; `FIXTURE_UNAVAILABLE` simulates playlist items `videos.list` won't return.
- **`GET /api/jobs/:id` now requires the requesting user (or admin)** — it exposed ingestion results to anyone with a job ID.

## Audit implementation round (2026-11-09, `ATLAS_IMPLEMENTATION_PLAN` + `DEFERRED_AUDIT_FINDINGS`)
Plan phases 0–4 were verified against the `feat/approval-coverage-compliance` work (policy gates, transcript isolation, proposals, coverage, compliance lifecycle) and kept; this round fills the remaining gaps and the deferred findings. On conflict the implementation plan wins over the deferred-findings recommendations.
- **Classification provenance (plan Phase 2 / D9)**: `ChannelNiche.classifier` + `ChannelNiche.evidence` JSON (score components and weights, matched keywords, matched topic-category URLs, source fields, the recent video IDs used as text, taxonomy content hash `TAXONOMY_VERSION`, embedding model id, threshold). Manual labels are `origin: user-authored` — alternative: separate score-component columns (rigid when the formula changes).
- **Topic evidence timestamp ranges** now carry `startSec` + `endSec` per supporting chunk and an explicit `confidence` — the plan's `timestampRange` / `confidenceScore`; kept in the existing `VideoTopic.evidence` JSON rather than new columns, since a topic can be supported by several chunks.
